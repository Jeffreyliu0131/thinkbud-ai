# Public baseline and strengthening audit — 2026-08-27

## Executive conclusion

The public `thinkbud-ai` snapshot already contained a substantial, sanitised product prototype and a clear Socratic tutoring contract. Its binding gap was not feature count: safety checks were primarily post-hoc, product-behaviour evaluation was not published as a reproducible evidence chain, RTC did not share the text-output safety boundary, and there was no license/provenance/release-readiness contract.

This strengthening was integrated directly on top of the public snapshot. Private deployment documents, local paths, credentials, production identifiers, internal planning history, and real user data were not imported.

## Public baseline boundary

| Area | Public baseline | Gap addressed |
|---|---|---|
| Code tests | Broad unit/component/hook/API coverage | Passing tests did not include a versioned behavioral eval or release evidence manifest |
| CI | Install, dependency audit, tests, build, lint | No explicit typecheck/eval/provenance/full-release contract |
| Text safety | Server prompt plus post-hoc audit | A leaked answer could reach the browser/TTS before post-hoc logging |
| Input trust | OCR sanitisation existed in selected paths | Client history, learner context, extraction, resume, and RTC preparation were not one shared boundary |
| RTC | Rich real-time path and fallback behavior | Managed speech bypassed application output guarding and had no safe default-off release flag |
| Open collaboration | Public source, README, security note | No project license, contribution templates, asset attestation, or release checklist |

## Public-safe changes

- Added shared untrusted-input boundaries across OCR, chat history, learner context, RTC context, and knowledge extraction.
- Added a blocking text-output guard before SSE reaches display or TTS; detected leakage is replaced with a grade-appropriate safe question.
- Kept the public snapshot's newer lazy-loading, knowledge extraction, RTC analytics, SSE preservation, and failure-recovery behavior.
- Disabled RTC by default because managed RTC speech cannot pass through the application output guard.
- Added a versioned 38-case synthetic eval, negative controls, failure taxonomy, human rubric, grader-calibration contract, generated JSON/HTML evidence, and a fail-closed full release check.
- Added CI/typecheck/eval/provenance checks, contribution/security templates, architecture, privacy, pilot, provenance, release, demo, and case-study documents.
- Removed the unused external UUID dependency, refreshed the public lockfile, and reached zero known npm advisories at verification time.

## Residual risks

1. Managed RTC speech still bypasses application output guarding; it remains disabled by default.
2. The text guard is pattern-based and can both miss novel leakage and conservatively block valid equation restatements.
3. Synthetic evals validate deterministic mechanisms, not real model behavior, learning outcomes, or adoption.
4. Child-data governance still lacks completed DPIA, consent/notice, retention/deletion, vendor-processing, admin-access, and incident evidence.
5. The repository remains publicly viewable source, not open source, until the owner selects a license and completes asset attestation.
