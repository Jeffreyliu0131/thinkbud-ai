# ThinkBud 多题会话管理设计 v1

## 概述

支持"拍一页作业，逐题辅导"的核心能力。AI 从 OCR 文本中识别多道题目，在对话中自行管理辅导进度。

## 交互模型

```
用户拍照 → OCR 识别整页 → AI 说"这页有 X 道题，你想从哪道开始？"
→ 用户选择（或默认第一道）
→ 逐题辅导（苏格拉底式，共享核心框架）
→ 完成一题 → 鼓励 + 进度 + 询问下一步
→ 用户可跳题、可说"我会，跳过"
→ 全部完成或退出
```

## AI 自管理模式

所有题目信息在会话开始时一次性写入 system prompt。AI 在对话中自行维护进度。前端不追踪、不干预。

### 优点
- 简单，不需要前端改动
- RTC 原生支持（无需 META 信号）
- 推翻成本低

### 局限
- 管理后台无法精确看到每题完成状态
- AI 可能"忘记"已做过的题（context window 限制）

### 未来升级路径
- 通过 RTC 回调 webhook 或对话后分析提取结构化进度
- 前端结构化 OCR 预解析替代 AI 自行解析

## Prompt 注入格式

```
## 本页作业信息
本页共 6 道题（3道数学、2道语文、1道英语）：
- 第1题：3x + 6 = 9（数学）
- 第2题：两位数减法 45 - 28（数学）
- 第3题：看图写话：春天（语文）
- 第4题：选择正确的单词填空（英语）
- 第5题：阅读理解第一段（语文）
- 第6题：口算 12 × 5（数学）
```

## 多题管理规则

### 开始
- 告诉学生题目数量和学科分布
- 不逐题念完整题目
- 问学生想从哪道开始

### 完成一题后
- 简短鼓励 + 告知进度 + 询问下一步
- 不自动跳到下一题（给学生选择权）

### 跳题
- 用户随时可跳到任意题号
- AI 不质疑跳题行为
- 用户说"我会" → 直接跳过

### 全部完成
- 总结（题数 + 学科分布）
- 有跳过的题 → 提醒但不勉强

### 退出
- 用户说"不做了" → 不勉强，记录进度

### 学科切换
- 自动切换引导策略
- 用户无感知

## 变式迁移规则

**默认不出变式题。** 仅当学生主动要求时才出（"能再给我出点题吗""举一反三"）。

原因：作业页本身就是最好的"变式题集"。额外出题会让孩子觉得在增加作业负担。

## 降级处理

OCR 识别不清晰 / 无法分割题目时：
- AI 回退到单题模式
- 让学生指定要做哪一道
- 不猜测题目分割

## 调用方约定

| 调用方 | 责任 |
|--------|------|
| 前端 | 将 OCR 原始文本作为用户消息发送；构建 SessionContext（如有结构化解析） |
| prompt 层 | 接受 SessionContext，生成多题信息块注入 system prompt |
| AI | 在对话中自行管理多题进度 |

RTC 模式下 system prompt 在会话开始时设置一次，中途不可更改。
